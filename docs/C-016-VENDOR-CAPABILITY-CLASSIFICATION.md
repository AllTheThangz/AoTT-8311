# C-016 vendor capability classification

**Status:** source discovery complete for the current PRX126 vendor rootfs. Product implementation and hardware qualification are separate gates.

C-016 extends configuration discovery beyond the 55 controls currently rendered by AoTT. It examines the offline vendor UCI option names and the installed Dropbear/uHTTPd init-script consumers without reading any live ONU value.

The canonical machine-readable record is [C-016-VENDOR-CAPABILITY-REGISTRY.json](C-016-VENDOR-CAPABILITY-REGISTRY.json), generated by \`tools/build_c016_vendor_capabilities.py\`.

## Current discovery result

- **13** vendor UCI configuration domains.
- **89** option names present in those vendor configuration files.
- Additional native Dropbear/uHTTPd options discovered from the installed init scripts, including options not present in the current default config file.
- **127** classified capability records after merging vendor-config and native-consumer discovery.
- **0 unclassified records**.
- **26** product or expert control candidates beyond the current AoTT field set.
- **13** low-level PON candidates restricted to the experimental/test-OLT lane.
- Generic firewall, rpcd and ucitrack schema fields are classified as framework plumbing, not inflated into dozens of fake product features.

## Product control candidates

The source confirms native runtime consumers for residentially useful access/server controls including:

- SSH password authentication, root-password authentication, port, root-login policy, keepalive, idle timeout, authentication-attempt limit, service enable, mDNS and gateway-port behavior.
- LuCI session timeout.
- uHTTPd HTTP/HTTPS listeners, script/network timeouts, keepalive behavior, request/connection bounds and RFC1918 filter behavior.

\`dropbear.DirectInterface\` is **not** an independent user knob in V3. It is now a dependency owned by the guarded management transaction so SSH follows the management interface between \`lct\` and tagged \`mgmt\`.

Advanced Dropbear fields such as \`ForceCommand\`, \`BannerFile\`, \`RecvWindowSize\`, \`Interface\` and keyfile overrides remain classified as expert candidates rather than silently ignored.

## Test-OLT / experimental PON candidates

Low-level vendor PON options such as \`key_size\`, \`mode\`, \`plev_cap\`, \`psk\` and the PLOAM timeout family are source-discovered but remain **experimental/test-OLT only**. A source option name is not proof that changing it is useful, reversible or provider-compatible.

## A-to-Z rule

For every product candidate promoted from this registry, V3 still requires:

1. bounded type/range validation;
2. preview of the proposed change;
3. a fixed native write path;
4. durable readback;
5. actual runtime-consumer verification where independently observable;
6. restart/reload semantics;
7. reboot/bank persistence where applicable;
8. rollback/recovery for settings that can interrupt access;
9. negative/error/concurrency testing;
10. platform-specific qualification evidence.

This registry authorizes no live mutation and does not change the current hardware-qualified count.

## Privacy and scope

The registry contains option **names and classifications only**. It does not contain subscriber identifiers, PON credentials, addresses, current configuration values, private keys or live-device exports. The analysis uses the offline extracted vendor rootfs.
