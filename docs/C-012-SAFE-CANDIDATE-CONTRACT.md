# C-012 lower-risk candidate readiness contract

**Status:** source-only readiness analysis after the first committed-r9
read-only hardware baseline.

The C-012 qualification matrix intentionally places `lang`, `hostname`,
`timezone`, and `ntp_servers` in the lower-risk mutation lane. This
document adds a stricter rule: **lower risk does not mean ready to mutate**.

The deterministic contract is
[`C-012-SAFE-CANDIDATE-CONTRACT.json`](C-012-SAFE-CANDIDATE-CONTRACT.json),
generated by
[`tools/build_c012_safe_candidate_contract.py`](../tools/build_c012_safe_candidate_contract.py).

## Current readiness

| Field | Current source activation | Current independent effect evidence | Full end-to-end mutation test ready? |
| --- | --- | --- | --- |
| `lang` | Live UCI update after save | Configured UCI only; active LuCI session language is not independently proven | No |
| `hostname` | Next startup | Kernel hostname readback exists and was observed on the committed r9 baseline | No, current path needs an authorized reboot/persistence test |
| `timezone` | Next startup | Configured UCI only; active local-time/timezone behavior is not independently proven | No |
| `ntp_servers` | Next startup | Configured UCI only; configured servers do not prove a running synchronized NTP path | No |

Therefore **zero of four** candidates is currently ready for a complete
end-to-end live qualification under the full C-012 contract.

All four can support a bounded partial test of validation, preview, durable
environment write and exact durable readback once separately authorized, but
that is not enough to call the field functional.

## Source facts that enforce this boundary

The shipped r9 configuration backend explicitly labels only `lang` as
"Web interface after save". Other configuration changes are described as
"Next startup; live consumers may also re-read it".

The backend also contains an explicit live UCI write for
`luci.main.lang`. It does not contain equivalent live activation for
`hostname`, `timezone`, or `ntp_servers`.

The installed effective-device model independently reads the running kernel
hostname, but explicitly records these limitations:

- LuCI configuration is not proof of the active session language.
- UCI `zonename` is not proof of active local-time behavior.
- Configured NTP servers do not prove synchronization.

## Required source work before a complete low-risk live test

### Language

Add an independent authenticated read-only observation of the language used by
a newly rendered LuCI request/session. A future test must capture the original
value, preview the exact diff, apply one supported alternate value, observe the
new request language, restore the original value, and independently observe
the restore. No reboot should be needed.

### Hostname

The independent effect verifier already exists. A complete test still requires
a separately authorized reboot because the current generic apply path records
the change for next startup rather than changing the running kernel hostname.
The test must prove durable write, reboot effect, and revert/reboot recovery.

### Time zone

Add an independent runtime local-time/timezone verifier rather than treating
the UCI `zonename` as the effect. The current activation path is next
startup, so persistence and recovery require an authorized reboot test.

### NTP servers

Add a privacy-preserving runtime verifier that can establish the running NTP
configuration and bounded synchronization evidence without returning server
names or addresses. The current activation path is next startup, so a complete
test also requires reboot persistence and revert evidence.

## Safety boundary

This contract is source-only. It performs no SSH, HTTP, UCI, environment,
firmware-bank, or reboot action. The generated JSON contains no live setting
values. It does not authorize any device mutation.

The next implementation task is to add the missing **read-only effect
verifiers** before asking the production reference unit to exercise the
corresponding mutation path.
