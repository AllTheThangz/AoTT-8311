# C-012 lower-risk A-to-Z source readiness contract

**Status:** source implementation ready for bounded live qualification; hardware qualification is still pending.

The C-012 qualification matrix places `lang`, `hostname`, `timezone`, and
`ntp_servers` in the lower-risk mutation lane. The V3 development tree now
contains the missing live activation, independent runtime readback, and rollback
primitives for all four.

This document does **not** authorize a live change. It records that the source
path is now complete enough to perform a separately authorized A-to-Z
qualification without requiring a reboot merely to observe the runtime effect.

The deterministic machine-readable contract is
[`C-012-SAFE-CANDIDATE-CONTRACT.json`](C-012-SAFE-CANDIDATE-CONTRACT.json),
generated by
[`tools/build_c012_safe_candidate_contract.py`](../tools/build_c012_safe_candidate_contract.py).

## Current readiness

| Field | Live activation | Independent runtime verifier | Source ready for bounded live qualification? | Hardware qualified? |
| --- | --- | --- | --- | --- |
| `lang` | Commit `luci.main.lang`; next authenticated LuCI request uses the new language | Request language captured from the authenticated LuCI render | Yes | No |
| `hostname` | Commit system UCI and reload the native system service | `/proc/sys/kernel/hostname` | Yes | No |
| `timezone` | Commit system UCI and reload the native system service | Active `/tmp/localtime` zoneinfo target | Yes | No |
| `ntp_servers` | Commit native timeserver list and reload `sysntpd` | Active `ntpd` process `-p` peer arguments | Yes | No |

All four paths also have a rollback contract. A configured-value mismatch,
runtime-effect mismatch, reload failure, or later transaction failure causes
the reviewed save to attempt restoration of both the live native configuration
and the durable boot-environment values.

## What changed from the earlier contract

The earlier contract correctly reported that only language had an immediate
UCI write, hostname was next-startup-only, and timezone/NTP lacked independent
runtime verifiers.

That limitation is removed in the current V3 development tree:

- `hostname` now reloads the native system service and verifies the running
  kernel hostname.
- `timezone` now reloads the native system service and verifies the active
  zoneinfo target.
- `ntp_servers` now reloads native `sysntpd` and verifies the configured
  peers from the running daemon's process arguments.
- `lang` remains special because the same request cannot prove its own new
  language. The save marks the effect pending until a subsequent authenticated
  LuCI request exposes the active request language.
- The general configuration transaction now distinguishes durable
  boot-environment verification from live runtime-effect verification and can
  restore the reviewed save when activation fails.

## What remains before FULLY_QUALIFIED

Source readiness is not hardware qualification. Each field still requires a
separately authorized live qualification on the named platform:

1. Capture the original saved, configured, and observed runtime state.
2. Preview the exact proposed diff.
3. Apply a reversible alternate value.
4. Verify durable boot-environment readback.
5. Verify the native UCI/configured state.
6. Verify the actual runtime consumer.
7. Restore the original value.
8. Verify the durable and runtime restore.
9. Reboot and verify persistence of a deliberately applied value and its
   subsequent restored baseline.
10. Record positive, negative, rollback, and postboot evidence.

For NTP, peer configuration is **not** treated as proof that the clock
successfully synchronized with a remote server. Clock-synchronization evidence
is a separate diagnostic property.

## Safety boundary

This contract performs no SSH, HTTP, UCI, environment, firmware-bank, reboot,
or live device action. It contains no live setting values or credentials.

A generic instruction to continue does not authorize exercising the live
mutation path. Hardware qualification remains zero until an explicitly
authorized apply/verify/restore sequence is completed.
